## 2. 다음 작업 — 우선순위

### ① 배분 UI를 포인트 20개로 ★ 다음에 할 것

**지금 화면과 랜딩이 어긋나 있다.** 랜딩은 "6개 전선에 포인트 20개"라고 광고하는데
실제 화면은 6축 퍼센트 `+`/`−` 버튼이다. 이 불일치부터 없애야 한다.

| 파일 | 할 일 |
|---|---|
| `lib/portfolio/weights.ts` | **`adjustWeight`의 비례 재조정을 없앤다.** 지금은 한 축을 올리면 나머지가 자동으로 깎여 합이 항상 100이 된다. 이게 사용자가 자기 선택을 인지 못 하게 만드는 원인 |
| `components/weight-editor.tsx` | 퍼센트 → **포인트 20개** 표기로 전환. % 는 작은 글씨 병기 |
| 〃 | **전 축 0에서 시작.** 각 축 독립 조정. 합이 20을 넘을 때만 막는다 |
| 〃 | **미배치분을 「예비대」로 상시 표시.** "0%"가 아니라 "예비대 7포인트" |
| `lib/constants.ts` | `PORTFOLIO_TEMPLATES` 4종 → 작전 5종으로 교체 (§DESIGN-DECISIONS 11-B) |

**중요 — 「예비대」가 필요한 이유** (지우면 안 되는 설계):
전부 0에서 시작 + 현상유지 편향이 겹치면 서비스가 과소투자를 훈련시킨다.
Benartzi & Thaler가 관찰한 실패 양상이 정확히 그것이다.
미배치분을 **보이게** 만들어야 방치가 아니라 선택이 된다.
문구: "잃지 않음. 다만 물가만큼 조용히 줄어듦."

**포인트는 쪼개지지 않는 병력 단위로 다룬다.** 상위 전선에 5포인트를 놓았으면
하위 테마에서 그 5개를 다시 나눈다. 1포인트 전선은 분할 불가 — 집중의 물리적 한계를 가르친다.

```

                  → bash scripts/verify.sh 의 DB 항목 전부 FAIL
```

**코드 문제가 아니다.** DB 없이 도는 검증 항목만 신뢰할 것.

### 로컬 확인 방법

```bash
DATABASE_URL="postgresql://u:p@localhost/db" npx next dev --port 3111
```

- `/` (랜딩), `/onboarding` 은 DB를 안 써서 **더미 URL로도 200**
- `/home`, `/portfolio` 등은 **실제 DB 세션이 필요해 로컬 확인 불가**
- 커밋 메시지에 무엇을 검증했고 무엇을 못 했는지 정직하게 적을 것
