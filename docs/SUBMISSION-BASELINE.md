## 3. 왜 루트 URL 인가

`/demo` 를 제출하면 심사자는 랜딩을 건너뛰고 `/home` 의 «다음 편성까지 D-n» 부터 본다.
그 화면은 «무엇을 하는 서비스인가»를 말하지 않는다 — 그 설명은 전부 랜딩에서 끝내기로 했다(`app/page.tsx` 상단 주석).
루트로 들어오면 §0 문장 → 2,000만원 → 주말 한 번 → 포인트 20개 → 제대로 지수 → **[3분 심사 데모 시작]** 순서로
기획서 목차와 같은 순서로 읽힌다.

## 3-2. DB 재시드 — 정확한 절차

`scripts/seed.ts:181` 이 「이번 주 포함 4주치」 주간 점수를 미리 넣는다. 지금 프로덕션 DB 는
그 창 밖에서 시드돼 이번 주(ISO 2026-37) 행이 없다. 심사 창 09-07~09-11 이 전부 37주차다.

```bash
cd <이 저장소>
printf 'DATABASE_URL=%s\n' '<Neon 프로덕션 URL>' > .env   # .env 는 .gitignore 안에 있다
npm run seed
```

기대 출력: `더미 사용자 200명 (동의 150) · 배분 600 · 주간점수 800`

**안전한가.** `seed.ts:198` 이 지우는 대상은 `settings.seed_dummy_user_ids` 에 기록된 더미와
레거시 목록뿐이다. 심사자·체험 세션 계정은 건드리지 않는다. 지금 돌리면 36~39주차가 채워져
**09-27 까지** 커버된다. 심사 창이 11:00 에 열리므로 아직 아무도 들어와 있지 않다.

확인:

```sql
select week_of, count(*), count(total) from weekly_scores group by 1 order by 1;
```

`2026-37` 줄이 나오면 닫힌 것이다. 화면으로는 주말 → 지수 → 「같은 군종」 탭에서 점수가 보인다.

**덤.** `.env` 에 `DATABASE_URL` 이 들어가면 `bash scripts/verify.sh` 의 DB 항목 7건
(P0-02·04·05·09·11 · P1-07·13)과 진짜 `npm run build` 까지 같이 돌아간다. 지금은 그 7건이
「DATABASE_URL 없음」으로 건너뛰어져 있다.
