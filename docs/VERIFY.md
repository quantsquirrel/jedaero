# 검증 항목

두 가지 용도를 겸한다.

1. 개발 중 자기 검증 (`scripts/verify.sh`)
2. **제출용 기능명세서 §5 "MVP 검증 방법"** — 양식이 테스트 계정·샘플 입력·예상 결과를 요구한다. 버리지 말 것.

---

## A. 자동 검증 — `scripts/verify.sh`

각 항목을 `PASS` / `FAIL` 한 줄로 출력하고, 하나라도 FAIL이면 exit 1.

출력 형식 고정:

```
[P0-01] PASS  npm run build exit 0
[P0-02] FAIL  테이블 10개 목록 불일치: holidays 없음
...
---
P0: 12/14 PASS   P1: 0/13 PASS
```

### A-1. 부대 정보 검사 스코프 규칙 ★

> **단순 grep을 쓰면 반드시 오탐이 난다.** 이 저장소에는 부대 관련 단어가 **합법적으로** 존재하는 곳이 있다.

**검사 대상 (포함)**

```
db/schema.ts          ← 컬럼명·테이블명
db/migrations/*.sql
app/**/*.tsx          ← 입력 폼 라벨·placeholder
components/**/*.tsx
```

**검사 제외 (오탐 발생지)**

| 경로 | 제외 이유 |
|---|---|
| `*.md`, `docs/` | 명세서가 금지 사항을 설명하면서 해당 단어를 쓴다 |
| **`lib/filters/unit-filter.ts`** | **AI-5 필터의 정규식이 `사단\|여단\|연대\|대대`를 반드시 포함해야 한다** |
| `**/*.test.ts` | 차단 테스트가 `12사단 3대대`를 샘플로 쓴다 |
| `db/seed/demo.ts` | 더미 그룹명 차단 사례 검증용 |

> ⚠️ **AI-5 필터와 그 테스트를 지워서 P0-03을 통과시키지 말 것.** 그 정규식은 이 서비스의 핵심 차별점이다. 검사가 필터를 잡으면 **검사 범위가 틀린 것이지 필터가 틀린 게 아니다.**

**찾을 패턴** (위 범위 안에서 0건이어야 함)

```
unit_id, unitId, unit_name, unitName, division, battalion, regiment, brigade
소속부대, 부대명, 사단, 여단, 연대, 대대, 중대, 소대
```

## C. TWR 테스트 케이스

```
구간 1: V0 = 1,000,000,  C1 = 0,        V1 = 1,100,000
        r1 = 1,100,000 / (1,000,000 + 0) − 1 = 0.10

구간 2: V1 = 1,100,000,  C2 = 500,000,  V2 = 1,760,000
        r2 = 1,760,000 / (1,100,000 + 500,000) − 1 = 0.10

TWR = (1.10 × 1.10) − 1 = 0.21   → 21.00%
```

단순 수익률 `(1,760,000 − 1,500,000) / 1,500,000 = 17.33%` 와 **다르다.**
이 차이가 학습 카드 5단계의 내용이다. 이 훈련의 시드는 일시금이라 화면의 누적과 TWR이 같다. 적립식으로 바뀌면 갈라진다.
