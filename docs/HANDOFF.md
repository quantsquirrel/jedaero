## 6. 환경 함정 — 반드시 알고 시작할 것

### 세션은 프로젝트 폴더에서 시작할 것


### `.env`는 있는데 `DATABASE_URL`이 없다 ★ 이번 세션 내내 발목을 잡은 것

```
.env          존재함. gitignore 대상. KRX_API_KEY · DATA_GO_KR_API_KEY 만 들어 있음
              ★ DATABASE_URL 이 없다
.env.example  자리만 표시. 추적되는 파일이므로 여기에 실제 값을 절대 넣지 말 것
```

`.gitignore`에 `!.env.example` 예외가 있어 이 파일은 커밋된다.

`DATABASE_URL` 이 없으면:

```
npm run build          → 실패 (Failed to collect page data for /home)
                          ※ 컴파일·타입체크는 통과한 뒤 DB 연결에서 멈춘다. 코드 문제가 아니다
bash scripts/verify.sh → DB 항목 9건 전부 FAIL (P0-01·02·04·05·09·11·13, P1-07·13)
```

**로컬 Postgres로 대체할 수 없다.** `db/index.ts`가 `@neondatabase/serverless`의
`neon-http` 드라이버를 쓴다 — HTTP 엔드포인트가 필요하므로 일반 TCP Postgres에 붙지 않는다.
**Neon 연결 문자열이 있어야 한다.**

> P1-13은 예전에 이 상황을 "lib/ai/guard.ts 미구현 (3단계)"로 보고하고 있었다.
> 코드 문제로 오진하기 쉬워 원인을 구분하도록 고쳤다. 지금은 "DATABASE_URL 없음"이라고 나온다.


**커밋 메시지에 무엇을 검증했고 무엇을 못 했는지 정직하게 적을 것.**

- `main`에 직접 커밋하지 않는다. 작업 브랜치를 쓴다
- 동의만 하지 말고 **긴장 지점과 반대 의견을 명확히 제시할 것.**
  이 프로젝트에서 실제로 가치 있었던 것은 대부분 반대 의견이었다
  (데스크탑 두 벌 제작 반대 → 반응형 / 퀘스트 유지 주장 후 철회 / 가계부 제외의 AI 축소 리스크 정량화)
- 검증 결과를 보고할 때는 **실행한 명령과 원문 출력을 함께** 남긴다.
  못 한 검증은 못 했다고 적는다
