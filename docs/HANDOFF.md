### 1-B. 고친 결함 (전부 실제로 재현 확인함)

1. **`drizzle-kit generate`가 `drafts` 테이블을 두 번 만들던 문제** — `meta/0004_snapshot.json`이 없어서 drizzle이 0004를 못 보고 `0005`에 같은 `CREATE TABLE`을 또 만들었다(에러도 안 났다). 정식 재생성해서 스냅샷까지 맞췄다. **이게 있었으면 내일 마이그레이션이 중간에 죽었다.**
2. **도상훈련 픽스처가 서버 타임존에 흔들리던 문제** — `getDay()` 같은 로컬 시각 메서드를 써서 UTC−8 호스트에서 구간이 260일→259일로 밀렸다(P1-18 FAIL). UTC 고정 산술로 바꿔 UTC−11~+14에서 동일 확인.
3. **「가입순」이라 써놓고 `ORDER BY`가 없던 문제** — `lib/league.ts`·`lib/groups.ts`에 `ORDER BY created_at` 명시.
4. **`P0-11`이 옛 종목코드(`005930` 등)를 보던 문제** — 대표지수 6종으로 교체. 안 고쳤으면 **제출 직전 자체 검증에 빨간 줄이 남았다.**
5. **도상훈련에서 하위 테마가 무시되던 문제** — 전선당 곡선이 하나여서 「반도체 몰빵」과 「지수 추종」의 결과가 **0원 차이**로 같았다. 하위 테마를 대표지수보다 뾰족하게 만들어 이제 다르게 나온다.
6. **`'use server'` 파일에서 상수를 export하던 문제** — 서버 액션 파일은 async 함수만 export할 수 있다. `NOTE_MAX`를 `lib/drafts/compare.ts`로 옮겼다.

### 1-C. 새 방어선 — 숫자 가드 (`lib/ai/number-guard.ts`)

가장 큰 구멍이었다. 시스템 프롬프트 4곳이 전부 "주어진 숫자만 쓴다"고 적지만 **강제하는 코드가 없었다.** 기존 `output-guard`는 조언·라벨·전망 «어휘»만 본다.

규칙 하나: **출력의 숫자는 입력에 있던 숫자여야 한다.** 위반하면 기존 폴백 경로로 내려가므로 화면은 비지 않는다. AI-3·AI-4(평일/주말)·AI-7 넷 다에 걸었다.

**평일 손익 누출은 가드보다 앞에서 막았다.** 처음엔 가중 등락을 금지값으로 넣었더니 실측에서 **규칙 폴백의 14.1%가 함께 폐기**됐다. 그래서 구조를 바꿨다 — **평일 LLM 입력에서 내 비중을 아예 뺐다.** 재료가 없으면 곱할 수 없다. 실제 시드 256주간 재측정: **오탐 0.0%**.

> 발표용 한 줄: *"평일 LLM은 내 비중을 아예 받지 않는다."* — "프롬프트로 막았다"보다 훨씬 강하다.

## 2. ★ 배포 자리에서 주의할 것

### 2-1. 푸시

09-04 밤 구현은 커밋됐다. origin에 푸시하지 않으면 Vercel Preview는 잠금 문서 커밋만 본다.

### 2-2. `DATABASE_URL`이 없으면 **빌드부터** 죽는다

`db/index.ts`가 모듈 로드 시점에 `neon(process.env.DATABASE_URL)`을 부른다. 값이 없으면
`Failed to collect page data for /portfolio`로 **배포물 자체가 안 만들어진다.**

→ Vercel 환경변수를 **Production · Preview · Build 스코프 전부**에 넣고 눈으로 확인할 것.
값이 «있기만» 하면 되고 실제 연결까지는 필요 없다(가짜 주소로도 빌드 성공을 확인했다).

### 2-3. **기존 Neon DB를 재사용하지 말 것**

구버전으로 한 번이라도 시드된 DB라면 마이그레이션만으로 정리되지 않는다.

- `tickers`에 **삼성전자·KODEX 200 같은 실제 상품명이 그대로 남는다** (새 시드는 upsert라 옛 행을 안 지운다) — C10이 금지한 데이터가 DB에 남는 셈
- 더미 200명의 편성이 옛 전선 코드(`KR_LARGE` 등)인데 같은 주차라 `onConflictDoNothing`으로 **안 덮인다** → 곡선이 0이 되고 제대로 지수가 왜곡
- 마이그레이션 `0003`이 점수 컬럼을 `NULL`로 새로 만들어, 재시드 없이는 리그가 **전원 「집계 대기」**

→ **새 DB를 만들고 `0000`~`0004` 전부 적용한 뒤 `npm run seed`를 반드시 실행.**
사용자 데이터가 없으니 새로 만드는 게 제일 싸고 확실하다.

### 2-4. 테이블은 이제 **11개**다

`drafts`가 늘었다. `P0-02`가 11개 목록을 기대하므로 **`0004`까지 적용돼야** 통과한다.

```
ai_calls allocations drafts group_members groups holidays prices settings tickers users weekly_scores
```

### 2-5. 보안 브랜치 — 머지해도 작업은 «되돌아가지 않는다»

앞서 잘못 말했던 부분이다. 실제로 시뮬레이션(`git merge-tree`)한 결과:

| 브랜치 | 결과 | 비고 |
|---|---|---|
| `security/f2` 초대코드 CSPRNG | **충돌 없음** | 그대로 머지 |
| `security/f3` 필터 우회 차단 | `SPEC.md`만 충돌 | 코드는 자동 병합 |
| `security/f8` 편제어 추가 | `SPEC.md`만 충돌 | f3와 **같은 정규식 한 줄**을 각자 고침 — 손으로 합칠 것 |
| `security/f9` 더미 UUID 난수화 | `scripts/seed.ts` 충돌 | 우리가 그 파일을 많이 고쳐서 |
| `security/f4` demo_day 쿠키 잠금 | 무거움 | 마이그레이션 번호 충돌 — **이제 `0005`로 만들어야 한다** (drafts가 0004를 씀) |

권장 순서: **f2 → f3 → f8 → f9 → f4**. f4는 DB 작업과 같은 자리에서.

> ⚠️ f3·f8을 넣은 뒤에는 **한 줄 회고에 정상 문장을 직접 넣어볼 것.**
> 그 정규식은 그룹명 전용이 아니라 `injection-filter.ts`를 통해 **회고 입력도 하드 리젝트**한다
> (`app/actions/learn.ts:35`). 넓히면 멀쩡한 회고가 막힐 수 있고, 화면에는 원인이 안 보인다.

### 2-6. 아직 뚫려 있는 것 (f3·f8 머지 전까지)

부대명 필터가 실제로 통과시킨다 — `제1보병사단` · `1보병사단` · `7기동군단` · `3군단` · `53전대`.
자체 테스트(`P1-11`)가 `12사단 3대대` 한 케이스만 봐서 지금까지 안 잡혔다.

### 2-7. 브라우저로 본 화면이 아직 `/`와 `/onboarding`뿐이다

**이게 남은 가장 큰 리스크다.** 배포 직후 실제 URL에서 `docs/VERIFY.md §B`의 시나리오를 훑을 것.
특히 오늘 새로 만든 것 — `/learn#drill` 도상훈련 3장, 평일 「오늘의 지형 요약」 버튼,
평일 `/portfolio`의 명령하달 초안, 주말 편성기의 「초안 불러오기」.
