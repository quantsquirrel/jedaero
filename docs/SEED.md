# 시드 데이터

`SPEC.md`가 참조하는 상수·시드 데이터. 값을 바꾸지 말 것.

## 1. 예시 작전 5종

`allocations.template_id`에 저장. 확정본은 `DESIGN-DECISIONS.md` §11-B.

**포인트 20개 기준.** 합계 100은 조건이 아니다 — 「정찰 침투」는 의도적으로 다 쓰지 않는다.

| id | 표시 이름 | 국내 주식 | 미국 주식 | 기타 해외 | 채권 | 금·원자재 | 리츠·인프라 | 예비대 |
|---|---|---|---|---|---|---|---|---|
| `ALLIANCE` | 연합작전 | 4 | 4 | 3 | 4 | 3 | 2 | 0 |
| `BREAKTHROUGH` | 돌파 | 7 | 8 | 3 | 0 | 1 | 1 | 0 |
| `DEPTH` | 종심 방어 | 2 | 3 | 1 | 9 | 4 | 1 | 0 |
| `STRONGHOLD` | 거점 확보 | 2 | 11 | 1 | 4 | 1 | 1 | 0 |
| `RECON` | 정찰 침투 | 2 | 3 | 2 | 3 | 2 | 1 | **7** |

각 카드에 함께 표시할 것:

- 시드 구간 기준 **누적수익률**
- 시드 구간 기준 **최대낙폭(MDD)**
- **성격 한 줄 + 장점 2 + 단점 2** (`lib/constants.ts`의 `OPERATIONS`)

> **★ 균형 규칙:** 다섯 작전의 +/− 개수와 문장 무게를 비슷하게 유지한다.
> 어느 하나가 정답으로 보이면 그 순간 예시가 아니라 추천이 된다 (C10).
> 이전 판의 `FOCUS`처럼 하나만 붉게 경고하는 처리를 되살리지 말 것.
> `scripts/checks/p0-10-templates.ts`가 장단점 개수 균형을 기계적으로 검사한다.

> **금지**: "추천", "안정형", "공격형", "위험중립형", "당신에게 맞는".
> **허용**: "예시", "작전", 위 작전명 그대로.

## 2. 지수 시드 (35종)

`tickers` 테이블. **더미 데이터이며 실제 지수와 무관함을 코드 주석에 명시할 것.**

**★ 개별 종목명·운용사 상품명을 쓰지 않는다 (C10).** 같은 섹터에 여러 운용사 상품이 있는데
하나를 골라 표시하는 것 자체가 특정 상품 지목이다. 전부 「지수(바스켓)」 수준으로 적는다.

```
✗  KODEX 반도체 / 삼성전자      ← 특정 상품·종목 지목
✓  국내 반도체 지수              ← 지수·바스켓 수준
```

구조는 **전선마다 대표지수 1종 + 하위 테마 N종**이다.
하위를 건드리지 않으면 그 전선은 **대표지수를 그대로 추종한다** (동일가중이 아니다).

| 전선 | 대표지수 (`kind: INDEX`) | 하위 테마 (`kind: THEME`) |
|---|---|---|
| `KR_STOCK` 국내 주식 | `KR-IDX` 국내 대표지수 | 반도체 · 2차전지 · 바이오·헬스케어 · 금융 · 산업재(조선·기계·방산) · 자동차 · 인터넷·게임 (7) |
| `US_STOCK` 미국 주식 | `US-IDX` 미국 대표지수(S&P500) | 빅테크·AI · 반도체 · 헬스케어 · 금융 · 소비재 · 에너지 · 배당 (7) |
| `INTL_STOCK` 기타 해외 | `IN-IDX` 신흥국 종합지수 | 일본 · 유럽 · 중국 · 인도 (4) |
| `BOND` 채권 | `BD-IDX` 종합채권 지수 | 국고채 3년 · 국고채 10년 · 회사채 · 미국채 (4) |
| `GOLD_COMM` 금·원자재 | `CM-IDX` 원자재 종합지수 | 금 · 은 · 원유·에너지 · 농산물 (4) |
| `REIT_INFRA` 리츠·인프라 | `RE-IDX` 리츠 종합지수 | 국내 리츠 · 미국 리츠 · 데이터센터·전력 (3) |

원본은 `db/seed/tickers.ts`. **방산은 산업재 안의 한 항목이며 특별 취급하지 않는다.**

> ⚠️ 티커 코드(`KR-SEMI` 등)는 **합성 라벨**이다. 실재 상품 코드가 아니며 그래야 한다.
> 화면에 "본 서비스의 시세는 교육용 모의 데이터입니다"를 표기한다.

## 3. 가격 시드 요구사항 ★

`prices` 테이블. **최근 12개월치 일별 종가** (영업일만, 주말·공휴일 행 없음).

### 필수 조건

| # | 조건 | 이유 |
|---|---|---|
| 1 | **중간에 -15% 이상 하락 구간 포함** (주식 3전선 + 리츠) | 낙폭이 없으면 리밸런싱·분산을 가르칠 재료가 없다 |
| 2 | 하락 후 **부분 회복** | 방어 자산과 주식의 순서가 구간마다 갈리게 하기 위해 |
| 3 | **★ 그 구간에 전 전선이 같이 빠지면 안 된다** | 여섯 개가 다 빨간색이면 「분산이 무엇을 줄이는가」가 사실상 거짓말이 되고, 리밸런싱을 가르칠 재료가 사라진다 (DESIGN-DECISIONS §4) |
| 4 | 하위 테마는 대표지수보다 변동성·낙폭이 큼 | 「같은 전선을 넓히는 분산」의 한계를 데이터로 보여준다 |
| 5 | 종가는 **정수** | 부동소수 금지 |
| 6 | 결정론적 생성 (시드 고정) | 재실행 시 같은 데이터 |

### 대표지수 제약 (`scripts/generate-prices.ts`가 강제)

| 전선 | 요구 | 실제 생성값 |
|---|---|---|
| `KR_STOCK` | MDD −17% ~ −30% | −25.9% |
| `US_STOCK` | MDD −16% ~ −28% | −20.7% |
| `INTL_STOCK` | MDD −16% ~ −29% | −19.2% |
| `REIT_INFRA` | MDD −18% ~ −33% | −30.8% |
| `BOND` | MDD −0.5% ~ −8% (얕게) | −7.6% |
| `GOLD_COMM` | **위기 구간 수익률 ≥ +6%** (안전자산 수요) | +22.9% |

금·원자재 전선은 안에서도 성격이 갈린다 — 금·은은 위기에 오르고 원유·농산물은 함께 빠진다.
이 갈림이 「같은 전선 안의 분산」과 「다른 전선을 여는 분산」의 차이를 보여주는 재료다.

### 생성 방식

```
기하 브라운 운동(GBM) + 지정 구간 주입
전선별 연간 변동성 / 기대수익:
  BOND        5% / 3%      GOLD_COMM  16% / 5%
  US_STOCK   18% / 13%     INTL_STOCK 19% / 9%
  KR_STOCK   20% / 10%     REIT_INFRA 21% / 9%
하위 테마는 변동성 ×1.4, 주입폭 ×1.35
주입 구간: 전체의 45% 지점에서 6주(30영업일) → 이후 10주(50영업일)에 80% 되돌림
주입 부호: dd < 0 하락, dd > 0 상승(안전자산)

★ 주식 전선의 기대수익(mu)이 채권보다 충분히 높아야 하고 되돌림도 얕지 않아야 한다.
  둘 중 하나라도 낮으면 방어형 작전이 수익률·낙폭 두 축 모두에서 나머지를 지배해
  예시 5종이 사실상 추천이 된다 (§1 균형 규칙 / C10). 값을 낮추기 전에 그 영향을 확인할 것.
```

생성 스크립트는 `scripts/generate-prices.ts`, 결과는 `db/seed/prices.ts`에 커밋한다.
**런타임에 생성하지 말 것.** 매 요청마다 값이 달라지면 안 된다.

## 4. 위클리 퀘스트 — 폐지

**퀘스트·XP·배지는 전부 제거됐다** (DESIGN-DECISIONS §7). `quests`·`quest_progress` 테이블도 없다.

폐지 이유: 퀘스트는 **접속 빈도를 늘리는 게임화**다. 이 서비스가 가르치려는 것은
주 1회 결정하고 오래 버티는 일이라 방향이 정반대다.
남기는 기준은 **"빈도를 늘리는 게임화 금지, 질을 높이는 게임화만"**이다.

> 폐지 전 `HOLD`(그대로 두기) 퀘스트가 담당하던 「아무것도 하지 않는 것도 유효한 선택」은
> 사라지지 않았다. 조정하지 않은 주에 행이 생기지 않는 구조와 회고 문구가 그 역할을 잇는다.
> **되살리지 말 것.**

## 5. 계급 상수

온보딩에서 계급을 받고 「같은 계급」 비교에 쓴다. **월 봉급은 화면에 띄우지 않는다.**

```ts
const SALARY_2026 = {
  PRIVATE:   750_000,   // 이병
  PFC:       900_000,   // 일병
  CORPORAL: 1_200_000,  // 상병
  SERGEANT: 1_500_000,  // 병장
} as const;
```

`TRANSPORT_CAP`(집까지 거리 구간 상한)은 가계부 면제용으로 들어 있었다. 가계부 제외 후 **제품 흐름에 쓰지 않는다.** 컬럼 `home_distance`는 주소 원문 없이 네 구간만 받는 용도로 스키마에 남아 있다.

## 7. 데모 시드 데이터

`/demo` 진입 시 주입.

| 항목 | 규모 |
|---|---|
| 편성 이력 | 12주치. **조정하지 않은 주 4주 포함** (행이 없는 주가 곧 「유지」) |
| 더미 사용자 | 200명 (제대로 지수·성향 분석 분포용). 30%는 예비대를 남긴다 |

> 지출 이력·예산 봉투·면제 청구는 가계부 제외와 함께 사라졌다 (DESIGN-DECISIONS §9).

더미 사용자 닉네임은 **실명처럼 보이지 않게** 생성할 것 (예: `해뜰날`, `강철비`, `초코우유`).

더미 사용자의 `users.id`는 실행할 때마다 UUID v4 난수로 만든다. `user_id` 쿠키 값이 세션
자격증명이므로 규칙적인 ID를 코드에 두지 않는다. 재실행 시에는 직전 ID 목록을
`settings.seed_dummy_user_ids`에서 읽어 관련 합성 데이터를 지운 뒤 새로 적재한다.
