# 디자인 규칙 — 야간 지형

기능을 고치거나 더할 때 **이 문서를 먼저 읽는다.** 화면을 새로 만들면서 여기 없는 색·크기·부품을
발명하지 않는다. 발명이 필요하면 문서를 먼저 고치고 그다음에 코드를 고친다.

- 하드 제약(결격 사유)은 `CLAUDE.md`. 이 문서는 그 아래에 있다 — 충돌하면 `CLAUDE.md`가 이긴다
- 왜 그렇게 정했나는 `docs/DESIGN-DECISIONS.md`
- 무엇을 저장/계산/폐기하는가는 `SPEC.md` §2-1

---

## 0. 세 줄 요약

1. **색은 토큰으로만.** `zinc-800`·`amber-400` 같은 리터럴 클래스를 다시 쓰지 않는다
2. **손가락으로 누르는 것은 44px 이상.** 버튼 기본 `h-11`, 입력창 `h-12`, 스테퍼 `size-10`
3. **신호색(amber)은 한 화면에 한 곳.** 지금 사용자가 할 수 있는 단 하나의 행동만 가리킨다

---

## 1. 색 — 토큰만 쓴다

값은 전부 `app/globals.css` 한 곳에 있다. 화면 코드에는 색 «값»이 없어야 한다.

### 표면 (바탕 6 : 표면 3 : 신호 1)

| 클래스 | 토큰 | 쓰는 자리 |
|---|---|---|
| `bg-background` | `oklch(0.145 0.005 286)` | 페이지 바탕 |
| `bg-card` | `oklch(0.192 0.006 286)` | 카드·패널 |
| `bg-secondary` / `bg-muted` | `oklch(0.238 0.007 286)` | 카드 «안쪽» 블록, 통계 타일 |
| `border-border` | `oklch(0.268 0.007 286)` | 카드 헤어라인 — 물러나야 한다 |
| `border-input` | `oklch(0.305 0.008 286)` | 입력창·버튼 테두리 — 만질 수 있는 것 |

★ `border-border`와 `border-input`을 섞지 말 것. **만질 수 있는 것의 경계만 또렷해야 한다.**
카드 테두리에 `border-input`을 쓰면 화면이 온통 버튼처럼 보인다.

### 글자

| 클래스 | 밝기 | 쓰는 자리 |
|---|---|---|
| `text-foreground` | 0.97 | 제목, 수치, 강조 |
| `text-muted-foreground` | 0.72 | 본문 |
| `text-faint` | 0.55 | 보조 설명, 캡션, 단위 |
| `text-faint/70` · `/50` | — | 그보다 더 물러난 것 (구분점, 힌트) |

네 단계를 넘기지 않는다. 다섯 번째 밝기가 필요하면 그건 위계가 아니라 정보 과잉이다.

### 의미색

| 클래스 | 뜻 | 규칙 |
|---|---|---|
| `text-primary` / `bg-primary` | **신호** — 지금 할 수 있는 하나의 행동 | 한 화면에 한 곳 |
| `text-up` | 오름 | 등락은 **사실이지 신호가 아니다.** 굵게·크게 하지 않는다 |
| `text-down` | 내림 | 오름과 같은 굵기·같은 채도. 손실을 더 크게 그리지 않는다 |
| `text-violet-300` 계열 | 생성형 AI | `SourceChip`/`AiNotice` 안에서만 쓴다 |
| `text-destructive` | 오류 | 사용자의 손실이 아니라 «시스템 오류»에만 |

★ `text-down`과 `text-destructive`를 섞지 말 것. 주가가 내린 것은 오류가 아니다.
★ 등락은 색만으로 전달하지 않는다. 항상 부호(`+` / `−`)를 함께 적는다 — 색각 이상 대응.

### 지수 사다리

제대로 지수 세 축은 `--chart-1` → `--chart-3`(같은 색상의 명도 사다리)를 쓴다.
`IndexGauge`가 이미 처리하므로 직접 색을 고르지 않는다.

## 2. 글자

- 본문 `font-sans` = IBM Plex Sans KR, 수치 `font-mono` = IBM Plex Mono (`app/layout.tsx`, next/font)
- **금액·비율·포인트·날짜는 전부 `font-mono tabular-nums`.** 자릿수가 흔들리면 비교가 안 된다
- 크기: 화면 제목 `text-2xl~3xl` / 카드 제목 `text-base` / 본문 `text-sm` / 캡션 `text-xs` /
  큰 수치 `text-3xl`. 그 사이를 새로 만들지 않는다
- 제목에는 `tracking-tight`, 한글 줄바꿈에는 `break-keep`, 문단에는 `leading-relaxed`
- 머리표(kicker)는 `text-[11px] font-semibold uppercase tracking-[0.18em]`

★ 런타임에 외부 폰트를 부르지 않는다. `<link>`로 fonts.googleapis.com을 추가하지 말 것 —
심사 기간(09-07~09-11) 외부 장애가 화면을 흔든다.

## 3. 크기 — 44px 규칙

| 컨트롤 | 크기 | 비고 |
|---|---|---|
| 버튼 기본 | `h-11` (44px) | 목록 안 보조 동작 |
| 버튼 `lg` | `h-12` (48px) | 화면의 주 행동 (편성 확정 등) |
| 버튼 `sm` / `xs` | `h-9` / `h-8` | 카드 안 부차 동작. **손가락 주 동선에는 쓰지 않는다** |
| 아이콘 버튼 `icon-sm` | `size-10` (40px) | 편성기 `+`/`−`. 가장 많이 눌리는 버튼 |
| 입력창 · select · textarea | `h-12` (48px) | `text-base md:text-sm` (iOS 확대 방지) |

★ `h-8` 컨트롤을 되살리지 말 것. 이 앱은 생활관에서 한 손으로 쓴다.
★ 아이콘만 있는 버튼에는 반드시 `aria-label`을 단다.

## 4. 레이아웃

- **앱 화면**: `app/(app)/layout.tsx`가 `max-w-md`로 가둔다. 화면 여백 `px-5 py-8`, 카드 사이 `gap-4`
- **랜딩**: 전폭. 본문 컬럼 `max-w-5xl px-6`
- 카드 안 여백은 shadcn `Card`의 `--card-spacing`을 따른다. 직접 `p-*`를 덮어쓰지 않는다
- 간격은 4의 배수만. `gap-2 / gap-3 / gap-4 / gap-6`
- 나란한 것(칩·버튼·타일)은 **`flex`/`grid` + `gap`** 으로 놓는다. 마진과 공백 문자로 띄우지 않는다

## 7. 상태와 오류 — 문구 규범

**이 서비스의 톤은 「사실 + 선택지」다. 꾸짖지 않고, 재촉하지 않고, 조언하지 않는다.**

- **잠김**: 잠근 사실만 쓰지 말고 **언제 열리는지**를 같은 문장에 쓴다
  → “주말에만 조정할 수 있습니다. 평일에는 편성 현황과 학습이 열려 있어요.”
- **마감**: 압박과 «안 해도 되는 선택»을 **같은 크기로** 나란히 둔다 (SPEC §3-5)
  → “마감까지 1일 8시간” 아래 같은 크기로 “조정하지 않으면 기존 편성이 그대로 유지됩니다.”
- **빈 상태**: 비어 있음을 나무라지 않는다. 카운터·배지로 압박하지 않는다
  → “초안 없이 주말로 가도 됩니다.”
- **집계 대기**: 0점으로 표시하지 않는다. “집계 대기”라고 적는다
- **오류**: `text-destructive`. 사용자 탓으로 읽히는 문장을 쓰지 않는다.
  **스택트레이스·내부 식별자를 화면에 노출하지 않는다** (CLAUDE.md)
- **성공**: `text-up`. 다음에 무엇이 일어나는지 함께 적는다
  → “확정됐습니다. 2026-09-07 종가로 반영됩니다.”
- **AI 응답 실패**: 규칙 기반 대체 문장으로 내려간다. 그때는 `SourceChip kind="rule"`로 바꿔 단다 —
  **규칙이 만든 문장에 AI 배지를 붙이면 그 자체가 거짓 고지다**
- 금지 워딩: “추천”, “최적”, “~하세요”(조언조), 목표가, 종목 지목 (C10)

## 8. 반응형 — 데스크톱과 모바일

기준 폭은 **390px(모바일) / 1440px(데스크톱)** 두 개다. 그 사이는 자연히 늘어나야 한다.

- 앱 화면은 `max-w-md`라 데스크톱에서도 모바일 폭이다. **앱 화면에 `md:` 분기를 남발하지 않는다**
- 랜딩만 분기를 쓴다: 기본이 모바일, `sm:`/`md:`로 데스크톱을 «더한다»
- **가로 스크롤 금지.** 긴 것은 `min-w-0` + `truncate`, 표·코드는 그 블록만 `overflow-x-auto`
- 한글은 `break-keep`. 긴 단어가 있는 칸에는 `min-w-0`를 잊지 않는다
- **도표(SVG)는 모바일 대체 화면이 반드시 있어야 한다.** `RecordFlow`가 본보기다 —
  `hidden md:block`(도표) / `md:hidden`(세 갈래 카드). 1000px 도표를 390px에 밀어 넣으면
  글자가 5pt가 되어 아무도 읽지 못한다
- `position: absolute`로 띄운 장식(스크롤 힌트 등)은 **짧은 화면에서 버튼을 덮는다.**
  실제로 812px 높이에서 「시작하기」 버튼을 덮은 적이 있다. 흐름 안에 두거나 `sm:` 이상에서만 띄운다
- 그림자·블러보다 **선과 표면 층위**로 깊이를 만든다 (저사양 단말 고려)

## 9. 접근성

- 포커스는 `focus-visible:ring-3 ring-ring/50`. 절대 `outline-none`만 남기지 않는다
- 현재 위치는 `aria-current="page"` (하단 네비가 이미 그렇다)
- 아이콘 버튼에 `aria-label`, 장식 SVG에 `aria-hidden`
- 아코디언·토글에 `aria-expanded`
- 정보를 색만으로 전달하지 않는다 (등락에 부호, 상태에 문구)
- 애니메이션은 `motion-safe:` / `motion-reduce:`로 감싼다

## 10. 하지 않는 것

| 금지 | 이유 |
|---|---|
| 리터럴 색 클래스 (`zinc-*`, `amber-*`, `emerald-*`, `rose-*`) | 테마가 두 곳으로 갈라진다 |
| 이모지를 아이콘으로 | 브랜드가 아니다. lucide 아이콘이나 인라인 SVG를 쓴다 |
| 슬라이더로 비중 조정 | 포인트는 유한하다. `+`/`−`만 (DESIGN-DECISIONS §3) |
| 축하 애니메이션·색종이·연속 접속 표시 | 과잉거래 유도. 게임화 금지 (C3) |
| 등수 숫자, 수익 «금액» 노출 | 정렬이 곧 등수가 된다 |
| 캔들 차트·상품 로고·국기 | 추상 지형만 (DESIGN-DECISIONS §14) |
| 두 곡선 합산 「총 자산」 타일 | 곡선은 일시금 하나 (CLAUDE.md) |
| 부대·실명·위치 입력란 | C4. 입력폼·컬럼·로그 어디에도 |
| 새 색·새 간격·새 폰트 크기 | 이 문서를 먼저 고칠 것 |

## 11. 검증 절차 — 화면을 고쳤으면 이만큼은 한다

```bash
npm run lint          # 경고 0 이어야 한다
npm run build         # ✓ Compiled + 타입 검사 통과까지 확인
```

**`npm run build`는 로컬에서 「Collecting page data」에서 멈추는 것이 정상이다.**
로컬 `.env`에 `DATABASE_URL`이 없기 때문이다 (SPEC §1-1). `Compiled successfully`와
타입 검사가 지나갔으면 통과로 본다. 진짜 빌드 확인은 Vercel 프리뷰가 한다.

★ **`npm run dev`가 떠 있는 동안 `npm run build`를 돌리지 말 것.**
둘이 같은 `.next`를 쓴다. 빌드가 dev의 매니페스트를 지워 화면이 `Internal Server Error`가 된다.
빌드했으면 dev를 죽였다가 다시 띄운다.

눈으로 볼 때:

- Chrome 확장이 응답하지 않으면 브라우저가 여러 개 연결된 것이다. `list_connected_browsers` →
  `select_browser`로 하나를 고른다
- 랜딩은 `Reveal`이 스크롤 진입 시 페이드인한다. **스크롤 직후 스크린샷은 반투명하게 찍힌다.**
  2초 기다렸다 다시 찍는다
- SVG를 겹칠 때는 **먼 것부터 그린다.** 순서가 뒤집히면 가까운 층이 먼 층에 덮여 실루엣이 사라진다

배포는 브랜치 → PR → Vercel 프리뷰 통과 → main 병합. `main`에 직접 커밋하지 않는다.

## 12. 남은 것 (2026-09-05 기준)

기능을 더할 여유가 있으면 이 순서로 본다.

1. **390px 실기기 확인** — 20칸 포인트 트레이가 모바일에서 너무 얇으면 10칸 2줄로 접는다
2. 앱 화면 카드 상단의 능선 룰 (`RidgeRule`) — 랜딩에만 들어가 있다
3. 홈 「오늘 할 수 있는 일」의 primary 강조를 요일에 따라 바꾸는 것 (지금은 주말만 amber)

디자인 원본(아트보드 11장, 조작 가능한 프로토타입)은 세션에서 만든 캔버스에 있다.
새 화면을 그릴 일이 생기면 거기 있는 화면과 같은 어휘를 쓴다.
