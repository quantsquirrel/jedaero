# AI 역할표 — 어디까지 AI 이고 어디부터 사람인가

> **역할 검증표란**, AI 가 맡은 판단과 사람이 확인할 기준을 나눠 적는 제출 전 표다.
> 금융 AI 서비스는 «AI 가 판단해 줬다»로 읽히는 순간 위험해진다. 이 표는 기획서 §AI 적용, 기능명세서 §처리 흐름,
> 발표 슬라이드 한 장에 **그대로** 들어간다. 코드 근거는 `CLAUDE.md` C8·C9·C10, `SPEC.md` §4·§5.
>
> 한 줄: **숫자는 규칙이 만들고, AI 는 문장만 만들고, 결정은 사람이 주말에 한 번 한다.**

## 1. 단계별 책임

| 단계 | 누가 | 무엇을 | 무엇을 **하지 않는가** | 사람이 확인할 것 | 코드 | 화면 표기 |
|---|---|---|---|---|---|---|
| ① 데이터 확인 | **규칙** | 일별 종가 시드, 공휴일, 요일 판정(서버), 거래 구간 존재 여부 | 실시간 시세·뉴스 본문을 넣지 않는다 (C6) | 오늘이 평일인지 주말인지 (토글 배너) | `lib/day-type.ts` `lib/portfolio/prices.ts` `lib/market-week.ts` | «평일 / 주말·휴일» 배지. AI 배지 **없음** |
| ② 계산 | **규칙** | 6전선 등락, 내 편성 가중 등락(주말만), 목표 vs 현재 갭, 누적 수익률(TWR), 제대로 지수 3축, 도상훈련 3장 | LLM 이 숫자를 만들지 않는다 | 갭 %p, 예비대, 3축 점수가 산정 근거와 맞는지 (랜딩 «무엇을 어떻게 계산했나») | `lib/portfolio/*` `lib/jedaero-index.ts` `lib/drill/*` | AI 배지 **없음** |
| ③ 입력 필터 | **규칙** | 회고·그룹명·초안 메모에서 인젝션·주민번호·계좌·부대정보 차단 | 차단 사유·입력 원문을 응답에 되풀이하지 않는다 | «입력에 허용되지 않는 패턴» 문구 | `lib/filters/injection-filter.ts` `unit-filter.ts` | 오류 문구만 |
| ④ 요약·되묻기 | **생성형 AI** | ②의 숫자를 받아 읽기 좋은 사실 문장 + **질문** (AI-3 회고 1개 / AI-4 주말 3개·평일 1개 / AI-7 성향 사실 서술) | 추천·전망·매매 방향·성향 라벨·«최적»·수익 약속 (C8·C10). 평일에는 **내 비중을 입력으로 받지도 않는다** | 배지가 붙어 있는가. 문장이 질문으로 끝나는가 | `lib/ai/briefing.ts` `reflect.ts` `narrative.ts` | **«생성형 AI 제안 · 확정은 본인이 합니다»** 배지 (C9) |
| ⑤ 출력 검증 | **규칙** | 조언 어미·라벨·전망 어휘 폐기(`output-guard`), 입력에 없던 숫자 폐기(`number-guard`), 분당 5·일 50 한도, 킬스위치 | 프롬프트만으로 막지 않는다 | 폴백이 떴을 때 «규칙 기반으로 동작» 안내가 보이는가 | `lib/ai/output-guard.ts` `number-guard.ts` `guard.ts` | 폴백은 AI 배지 **없음** + 안내 한 줄 |
| ⑥ 결정 | **사람** | 주말에 한 번 6전선 포인트 20개 배치·확정. 평일 초안은 메모일 뿐 체결 아님 | AI 가 대신 확정하지 않는다. 초안 «불러오기»는 한 번, 자동 적용 없음 | 카운트다운 옆 «조정하지 않으면 기존 편성 유지» | `app/actions/allocation.ts` `drafts.ts` DB `UNIQUE(user_id, week_of)` | 확정 버튼은 사람만 누른다 |

## 2. 심사자 질문에 대한 답 (한 줄씩)

| 질문 | 답 | 증거 |
|---|---|---|
| AI 가 숫자를 지어낼 수 있나 | 없다. 출력의 모든 수치는 입력에 있던 수치여야 하고, 아니면 폐기 후 규칙 폴백 | P1-21, `number-guard.ts` |
| 평일에 AI 가 내 손익을 말할 수 있나 | 없다. 평일 LLM 입력에 내 비중이 없다 — 재료가 없으면 곱할 수 없다 | P1-19, `briefing.ts` |
| AI 가 «채권을 늘려라» 같은 말을 할 수 있나 | 없다. 조언 어미·매매 방향이 감지되면 문장 전체를 폐기 | P1-16, `output-guard.ts` |
| AI 가 꺼지면 화면이 비나 | 아니다. 킬스위치·429·호출 실패 모두 같은 자리에 규칙 요약이 뜬다 | P1-13, 시나리오 18 |
| 어디까지가 AI 인지 사용자가 아나 | AI 문장 위에만 배지. 규칙 계산에는 배지가 없다 | P0-14, `ai-notice.tsx` |
| 결정은 누가 하나 | 사람. 주 1회, 일요일 21:00 마감. DB 제약이 강제 | P0-05·P0-09 |

## 3. 문서·화면에서 쓰지 않는 말 / 쓰는 말

| 쓰지 않는다 | 대신 |
|---|---|
| 추천 편성, 추천 비중 | **예시 작전** (연합작전·돌파·종심 방어·거점 확보·정찰 침투) |
| 최적 비중, 최적화 | 포인트 배치, 편성 |
| 수익 보장, 손실 방지, 목표가 | 누적 수익률(과거 사실), 도상훈련 결과(고정 구간) |
| 안정형 / 공격형 | 작전 이름 |
| AI 가 분석·판단·진단했다 | AI 가 **정리하고 되물었다** |
| 예약 주문 | **아직 실행되지 않은 메모** (명령하달 초안) |

## 4. 이 표가 무너지는 신호

- 배지가 없는 곳에 LLM 문장이 있다 → C9 위반. `grep -rn AiNotice` 로 사용처 대조
- 규칙 폴백에 배지가 붙어 있다 → «AI 아님»을 AI 로 표기한 것
- 화면에 «추천»이 보인다 → C10. `grep -rn 추천 app components`
- 평일 화면에 «이번 주 내 편성 기준 ±%» 가 보인다 → 지표 교체 깨짐 (SPEC §3-4)
