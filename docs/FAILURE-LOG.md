# 실패 로그

> **실패 로그란**, 입력·기대·실제·원인·수정 범위·재검증을 한 줄로 남기는 기록이다.
> 성공 화면 캡처는 심사에서 아무것도 증명하지 않는다. 심사자가 따라갈 수 있는 것은 «무엇을 넣었더니 무엇이 깨졌고 어떻게 닫았나»다.
>
> 이 표는 **기능명세서 §5 «MVP 검증 방법»** 에 그대로 옮긴다. 자동 검증의 정의는 `docs/VERIFY.md`, 이 파일은 그 검증이 **실제로 잡은 것**의 기록이다.
>
> 규칙
> - 입력 유형은 **정상 / 오류 / 경계** 셋 중 하나. 경계 = 정상과 오류 사이의 애매한 조건을 일부러 넣은 것
> - «실제»는 관찰한 그대로. 추측·해석을 섞지 않는다
> - 상태가 «열림»인 줄이 있으면 **기능 추가보다 그 줄이 먼저다**
> - 재검증은 실행한 명령과 마지막 출력 줄을 적는다. «PASS 했음»만 적지 않는다

## C. 아직 검증하지 못한 조건 (실패가 아니라 «모름»)

- 실제 심사자 기기의 브라우저 종류 — 삼성 인터넷·iOS Safari 구버전에서 `dvh`·`break-keep` 렌더링

- OpenAI 상한 도달 시 429 → 규칙 폴백 경로를 **실제 배포**에서 눌러본 적 없음 (로컬 P1-13 만)
- 보안 브랜치 f3·f8 머지 뒤 정상 회고 문장이 `injection-filter` 에서 하드 리젝트되는지 (HANDOFF §2-5 경고)
